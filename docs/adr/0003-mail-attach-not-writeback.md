# 0003 — 邮件事件只挂载,不自动回写状态

- 状态:已接受(2026-09-08)
- 关联:CONTEXT.md「挂载 / 回写 / 绑定」

## 背景

邮件是投递流程里最快的信号:面试邀约、感谢信往往比官网状态更新早几天。要不要让邮件直接驱动投递记录的状态?

状态已有两个来源:官网自动抓取、人工修正(人工 > 自动)。若引入「邮件自动回写」,就是第三种自动状态来源,需要一套三方仲裁。

## 决策

邮件事件只作为证据**挂载**在投递记录旁,不自动改状态。需要据邮件改状态时,由邮件行预填现有的人工修正流程,人确认后生效——修正优先级高于抓取,语义复用,不新增仲裁规则。

自动关联只在无歧义时发生(该公司恰好一条投递记录);歧义/平台系标签/无对应记录的邮件进未关联池,等人工绑定或保持独立。

## 后果

- 状态永远可解释:要么官网说的,要么人改的。邮件解读错误(客套话被当成感谢信)不会污染数据。
- 代价:状态更新多一次人工确认;邮件的及时性只体现在展示与通知层,不落在状态层。
- 与 `extractScheduleTip` 的「写错比不写更糟」原则一致。
