# 0006 — 岗位库双源分发:岗位包为默认源,维护者文档永不分发

- 状态:已接受(2026-09-11)

## 背景

控制台岗位库的岗位内容由上游供给。初版直接绑定维护者自己的腾讯智能表格(匿名读取,文档需「有链接即可查看」)。若开源给所有用户,只有两条路:每个用户绑定自己的文档(大部分用户没有、也不想维护),或者暴露维护者的文档地址(文档一旦改权限/删除,全部用户的数据通道同时断掉;且地址是维护者的私人资产)。

可选:用户各自绑定自己的文档 / 全员共享维护者文档直连 / 维护者导出数据快照分发。

## 决策

**双源制**:岗位源(Source)分两种——

- **岗位包(pack,默认)**:维护者导出的数据快照(jobs-pack.json)随仓库与安装包分发。用户零配置,点「同步」即从公开仓库 raw 直链拉最新,失败回落随包内置版本;`jobs.json` 的 `packUrl` 可换远程地址。
- **我的文档(doc,仅维护者)**:绑定腾讯智能表格直读,登录态/文档地址只存维护者本机。

对外分发铁律:**文档地址永不出维护者机器**。岗位包默认剥离内推码/联系人字段并清洗链接里的内推参数(`--full` 保留),岗位 ID 按清洗后内容重算。发布走流水线(同步→防呆→打包→推送),岗位数异常自动拦截。

## 后果

- 用户的岗位数据新鲜度取决于维护者的发布节奏,产品语义上这是「策展内容」,README 需如实标注「尽力而为」;
- 维护者停止维护即全部用户数据停更——内容单点依赖是该模式的固有代价,靠发布流水线把维护成本压到最低;
- 内推码对公开用户不可见是刻意的:内推是他人给的资源,默认不随开源扩散;维护者可用 `--full` 导出完整版供私密渠道;
- 用户侧永远不需要腾讯文档账号,隐私叙事(数据不出本机)不被破坏——拉取的是公开文件,不上报任何用户数据。
