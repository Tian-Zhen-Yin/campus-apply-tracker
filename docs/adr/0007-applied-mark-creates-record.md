# 0007 — 岗位库「已投」落投递记录

- 状态:已接受(2026-09-11)

## 背景

岗位库的「已投」原本与不投/关注一样是纯标记覆盖层,但投递总览只消费自动抓取记录与 apps.json 手工记录——用户点了「已投」,总览毫无感知,进度跟踪断链。可选:维持纯标记 / 总览渲染时虚拟并入 / 点击即落记录。

## 决策

点「已投」= 落标记 **并** 在 apps.json 创建一条 `origin: 'jobmark'` 的记录(状态「已投递」、appliedAt=点击当天、带岗位链接);总览来源列显示「岗位库」。同公司同岗位已有记录(精确匹配)则只标记不建。取消「已投」时仅回收**纯净**记录(origin='jobmark' 且状态未改过、未绑邮件);已进展的保留并提示。手工登记/迁移来的记录(无 origin)永不被该按钮创建或删除。

反向(总览已有记录 → 岗位库自动点亮已投)不做,维持「可能已投 ✓」提示式确认(ADR-0003 只提示不落标的原则)。

## 后果

- apps.json 出现 `origin: 'jobmark'` 记录;无该字段 = 手工(旧数据天然兼容)。
- 标记覆盖层语义不变:仍永不写回岗位源;联动只发生在本机 apps.json。
- 邮件绑定(maillinks)参与纯净判断:绑过邮件的记录视为已进展,取消标记不删。
